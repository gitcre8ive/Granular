Granular

Approved product requirements

Granular is a local note editor designed for precise, low-friction text highlighting, built around a single editor surface and text-aware pointer controls.

The core journey

Layout and surfaces

The first screen centers the note editor with a large editing box, a note title field, a target bar resting above it, and a left sidebar that starts with the default color only. The user can drag the bar down into the box and align its pin tips just above a text line. Additional color-filled pointer bars appear only after the user chooses “Add pointer bar,” picks a color in the modal, and confirms it. The active color button sits to the right of the bar; the add-pointer control sits nearby.

Core value

Users can move beyond standard text selection and operate at the character level: precise range selection, character-by-character adjustment, and quick switching among highlight colors without leaving the note. The app also lets the user clear a range instantly with a None control when they want a single-step removal.

Features and behavior

Editor input and persistence

  • The user can type or paste a short note into the main editor.
  • The title field accepts a custom title or fallbacks to “Untitled”.
  • Input persists in local browser storage after a refresh.
  • Ordinary text editing and deletion remains available without conflict with the highlight layer.

Highlight range selection

  • The horizontal target bar rests above the editor box and can be dragged down into it; the pin tips align just above the line to target.
  • The two pins define the selected range; moved away from the red inactive ends, they become active and target a character.
  • Blue borders show active endpoint characters only when the pin tips are positioned just above a valid text line.
  • Clicking the active color button fills the entire span between the pins, including endpoints and spaces.
  • Single-pin mode can highlight a single character.

Increment and decrement controls

  • The decrement button removes highlight coverage backward by one character at a time.
  • The increment button adds highlight coverage forward by one character at a time.
  • Holding either control speeds up the action.
  • Highlighting continues across lines when the range reaches the end of a line.
  • Decisions are bounded by the first pin, so the user can mark a left limit and remove only within that range.

Color pointer bars

  • The app shows default highlight and additional pointer bars as filled squares in the left sidebar.
  • The user can add a new pointer bar from a modal color selector.
  • Clicking a filled sidebar box activates that pointer bar and makes it the current color for highlighting.
  • The sidebar is organized in rows of four to keep the pointer stack visible and easy to scan.

Invalid and empty states

  • If no valid range is active, the app should not apply a highlight to the whole note.
  • Instead, it shows a clear prompt guiding the user to drag the bar and target a character range.
  • The user can target a single character if they leave one pin active and move the other to the inactive strip.

States and boundaries

  • First use: A blank note opens with default yellow highlight and no active range.
  • Idle editor: The note and controls are visible, with no highlight selected.
  • Range ready: Pin targets are active and the selected characters are visibly bordered in blue.
  • Highlight applied: The chosen color fills the range and remains until it is removed or adjusted.
  • Increment/decrement adjustment: The highlight expands or contracts by character with immediate visible updates.
  • Invalid range: The app shows guidance instead of doing anything broad or unpredictable.
  • Local persistence: The note remains after refresh.

What we're building

  • Single editor surface with note title and body
  • Target bar and draggable pins
  • Visible range activation and highlight application
  • Multiple filled pointer bars in a left sidebar
  • Increment and decrement highlight adjustment
  • Local persistence for the note content
  • Guided invalid-range behavior

Deferred and cut

  • Dedicated read-only note view
  • Settings or trash flow
  • List/grid note library and batch operations
  • Complex deletion and restoration rules
  • Full app-like organization features

Product decisions

  • The editor-first scope is intentional so the proof of concept stays visible and demoable within a short build.
  • The sidebar is the visible way to select and swap active color modes.
  • The blue activation border is the main state indicator before a highlight is applied.
  • Character-level precision is the defining product trait, and it remains the focus even when the user adjusts range size.
  • Local persistence keeps the app useful without requiring a broader notes-management system.

Open questions

  • Should the app support custom colors beyond the small preset palette for the prototype?
  • Should the helper prompt be temporary or permanently visible during editing?
  • Should local persistence be per note or limited to a single current note state?

These are minor enough to resolve in the build without changing the essential proof-of-concept boundary.
