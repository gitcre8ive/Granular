Granular · local-first proof of concept

How pointer pins find characters

Granular is a note editor for precise, multicolor text highlighting. A pin's screen position is translated into a real text character; keyboard shortcuts select pins or the bar, and arrow keys move them. Enter applies the active color to a targeted range when the editor is not focused. The palette and note are saved in this browser. Controls can be hidden while the title, Help, and editable note remain available. There is no account or remote service.

Reference route through the code

This route is a reference, not a walkthrough completed together.

  1. Pointer input — src/components/TargetBar.tsx

    targetPin combines the dragged pin's horizontal position with the bar's text-line height. Left/Right on a focused pin moves by character; Up/Down on the focused bar moves it vertically. handleSelectorShortcut in the same component maps Ctrl+Shift+[ and Ctrl+Shift+] to the pins and Ctrl+Shift+Backslash to the bar. The backslash shortcut matches physical Backslash and IntlBackslash codes and shifted |; the bar is the track root, so lookup checks the root itself as well as its descendants. Clicking or focusing elsewhere releases keyboard targeting.

  2. Coordinate geometry — src/lib/targeting.ts

    targetAtPoint compares the pointer with measured grapheme rectangles. adjacentCharacterOnLine moves a targeted pin without crossing a visual line; characterInDirectionAtPoint lets an untargeted pin step inward from a red zone. targetPercentForCharacter positions the pin on the bar.

  3. Range and feedback — src/lib/highlighting.ts

    getTargetRange turns active pin targets into a text range. The target decorations in targeting.ts provide the visible blue outline. In App.tsx, handleApplyShortcut delegates Enter to the same active-color action as the apply button when a valid range exists and focus is on the page or a targeting control; editor focus keeps normal Enter/newline behavior.

To change this, start here

  • Pin hit-testing and bar geometry: TargetBar.tsx and targetAtPoint.
  • Range boundaries, grapheme stepping, and highlight marks: highlighting.ts and incrementHighlight / decrementHighlight.
  • Palette choices and color conversion: ColorDialog.tsx and color.ts.
  • Hide/restore state and its always-available control: App.tsx > showControls. Help copy lives in HelpPanel.tsx; the Lucide image files are in devpost/images/.
  • Browser persistence and its failure messages: storage.ts.

A practice to reuse

The approved scope.md made precise highlighting the unique kernel and cut the notes library and trash flow. The checklist.md put pin-to-character mapping early, where hands-on checks with spaces, punctuation, wrapped lines, edges, and red-zone keyboard entry exposed real targeting problems before polish. The later visibility toggle was explicitly added as a controlled iteration rather than restarting the completed project.

On another project, name the one behavior that proves the idea, cut adjacent features that do not prove it, and test the riskiest assumption with representative input before building around it.

Run the app again

From the repository root, run npm install if dependencies are not installed, then npm run dev and open the local URL printed by Vite (normally http://localhost:5173).
